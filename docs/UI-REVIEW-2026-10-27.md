# YiiOffice 界面设计评审与优化方案

评审日期：2026-10-27 · 范围：`packages/ui/src/tokens.css`、6 个 app 的 renderer CSS（31,151 行）、shell 首页 / 标签栏 / 设置页、docs 编辑器功能区
方法：真实启动 `apps/shell/out`（Electron 45 构建，10-27 14:27）截图 1440×900 与 1100×760、浅色 + 暗色、`YIIOFFICE_LANG=zh-CN`；对比度按 WCAG 2.1 相对亮度公式实算，非估算。

**一句话结论**：视觉工艺在同类项目里属于上层（Chrome 级标签栏度量、真 RTL、暗色三入口齐备、token 分层职责清晰），但**设计系统的"比例尺"和"语义层"没有建立起来**——6 个墨色 token 实际只有 2 个可见层级、3 个排版 token 零引用、圆角 token 仅用 6 次而硬编码 500 次、功能区 5 份实现。同时**无障碍契约已被破坏 3 处**（实测 3.05 / 1.85 / 3.82）。这些不是审美偏好，是可以写进 CI 的量值。

## 1. 已经做得很好、不要动的部分

1. **标签栏是全项目工艺最高处**：40px 条带 / 34px 页签 / 240→104 收缩 / `radial-gradient` 凹脚 / hover 与 active 共用同一 `.tab-plate` 元素。这套度量有 Chrome 对照注释，改一个数值就会破坏对齐，**建议冻结**。
2. **token 分层职责划得干净**：chrome 色只进 `tokens.css`，文档内容色（纸张、单元格、图表调色板）明确排除在外。这个边界是对的。
3. **暗色三个入口齐备**：`[data-theme='dark']`、`@media (prefers-color-scheme: dark)`、`color-scheme` 声明都在，没有"漏网的浅色块"。
4. **RTL 是真做了**：Windows 交通灯让位、扩展名 `.docx` 的 bidi 隔离、卡片标题 LTR isolate——多数同类产品只做镜像翻转。
5. **动效可关闭**：`prefers-reduced-motion` 有兜底。
6. **颜色门禁思路正确**：`tools/check-theme-colors.mjs` 挡新增裸色。问题不在思路，在它只管 diff（见 §3.5）。

## 2. 问题清单（按修复收益排序）

### P0-1　`--text-tertiary` 在最常用底色上不达 AA（实测 2.85–3.05:1）

它被用在 22 处，且几乎全是 **12–14px 的必读信息**：`.recent-path`（文件路径）、`.recent-time`、`.recent-size`、`.search-path`、`.nav-count`、`.picker-empty`、`.empty`（`home.css`），以及空状态提示语。

这不是"装饰性灰字"——路径和修改时间是用户判断"打开哪一个文件"的唯一依据，而它在 `#f6f7f9` 上只有 **2.85:1**。截图里"暂无最近文件 — 新建或打开一个文件开始使用。"几乎融进背景，就是这个值造成的。

### P0-2　`--icon-muted` 1.85:1，但它承载的是可点击控件

`.star-btn`（收藏星标，`home.css:715`）、空状态文档图标、`.more-btn` 都取这个值。WCAG 1.4.11 对**有语义的 UI 部件**要求 3:1，星标在未收藏态下几乎看不见 → 用户找不到"收藏"这个操作。

### P0-3　accent 被当正文色用，且焦点样式有三套语言

- 正文误用：`.search-rerank-badge`（11px 粗体，`home.css:1711`）、`.timeline-role.assistant`（12px 粗体，`home.css:1500`）。11/12px 粗体**不属于** WCAG 的 large text（需 18.66px 粗体），因此 3.82:1 不达标。
- 焦点三套：`.btn:focus-visible` 用 `0 0 0 3px rgb(35 36 37 / 20%)` 黑晕（`home.css:888`）；`.account-btn:focus-visible` 用 `rgb(15 127 255 / 12%)` 蓝晕（`home.css:236`，12% 透明度在白底上肉眼难辨）；其余 20 处用 `outline: 2px solid var(--accent)`。
- `tabbar.css` **一条 `:focus-visible` 都没有**：`.tab-close`、`.tab-new-btn`、`.tab-overflow-btn` 是真实 `<button>`（已带 `aria-label`，这点做得对），键盘走到时只能回落到 UA 默认环，与全站视觉割裂。

### P0-4　暗色把 6 个墨色 token 塌成 3 个值

| token | 浅色 | 对白底 | 暗色 | 对 `#1e1e1e` |
| --- | --- | --- | --- | --- |
| `--text` | `#242424` | 15.52 | `#e4e4e4` | 13.11 |
| `--text-primary` | `#232425` | 15.55 | `#e4e4e4` | 13.11 |
| `--text-secondary` | `#606366` | 6.04 | `#a0a0a0` | 6.38 |
| `--text-tertiary` | `#909499` | 3.05 | `#a0a0a0` | 6.38 |
| `--text-muted` | `#616870` | 5.64 | `#949494` | 5.50 |
| `--text-dim` | `#605e5c` | 6.46 | `#a0a0a0` | 6.38 |

两个事实：浅色下 6 个值里 4 个挤在 5.64–6.46（`--text-secondary` 与 `--text-dim` 只差蓝通道 4 个数值，肉眼不可分辨）；暗色下 3 个 token 指向同一个 `#a0a0a0`，任何用它们表达的层级差异**在暗色下直接消失**。

数学上的硬约束：暗色 `#2a2a2a` 底上要过 4.5:1，最暗只能到 `#909090`（恰好 4.50）。也就是说**深色主题下根本放不下 6 级可区分的 AA 达标灰阶**——只有 2 级正文灰 + 1 级临界灰的位置。所以正确做法不是逐 token 调色，而是**收敛成 3 级语义再别名映射**（§3.2）。

### P1-1　排版 token 零引用，字号全靠硬编码

`--text-body-lg: 18px`、`--text-small: 14px`、`--text-caption: 12px` 三个 token **引用次数为 0**。与此同时 `home.css` 一个文件里就并存 11/12/13/14/16/17/18/20/28px 九档字号，其中 12px 与 13px 两个"元信息级"混用（`.recent-path` 12px / `.search-snippet` 13px / `.picker-empty` 13px / `.search-time` 13px / `.folder-unusable` 13px）。用户感知不到 1px 差异，只会觉得"这一列和那一列不太齐"。

### P1-2　圆角有 12 个档位，token 只用了 6 次

`4px` 146 次、`6px` 82、`3px` 81、`8px` 60、`2px` 52、`5px` 24、`12px` 18、`1px` 16、`10px` 15、`7px` 11、`16px` 6、`999px` 6。而 `--radius-6/-8/-12/-16` 全仓只被引用 **6 次**。

2/5/7/10 这四个档位在 6/8/12/16 的比例尺之外，它们的视觉差异（4px vs 5px、6px vs 7px）在 1× 屏幕上不可辨——纯粹是历史上不同人不同时刻手填的残留。

### P1-3　暗色下卡片"抬不起来"

`--bg-content: #1a1a1a` → `--surface: #1e1e1e` 的对比度只有 **1.044**，卡片与画布几乎同色，全靠 `--border: #3a3a3a` 的 1px 线撑出边界。截图里暗色的快捷卡片看起来是"贴"在背景上而不是"浮"在上面。深色 UI 的抬升惯例是**越高越亮**，这里亮度差不足以完成这个语义。

### P1-4　功能区（ribbon）5 份实现，且信息结构缺失

`@yiioffice/ui` 只导出了 `useRibbonCollapse` / `RibbonCollapseButton`（折叠状态），**没有 ribbon 的骨架**。于是 5 个 app 各写一套，共 157 条规则。

从 docs 编辑器 1:1 截图看到的具体问题：

1. **只有"粘贴"一个组有组名**，字体/段落/样式三组没有 caption。Office 的每个组都有居中组名，这是让用户理解"这一堆按钮属于同一类操作"的唯一线索。
2. **右半区只有一行控件**：左半区两行、`x>610` 只有一行（字体色 A + 样式窗格），形成 L 形空洞。视觉上像"还没做完"。
3. **图标尺寸四档混用**：剪贴板 24px、样式窗格 18px、功能图标 16px、对齐图标 14px，没有统一网格。
4. **激活选项卡辨识弱**：`开始` 与其余选项卡的差异不足以一眼分辨。
5. **"自动保存"开关没有开/关色**：灰色胶囊 + 12px 灰字，用户无法判断当前状态。
6. **组间分隔线不一致**：有的组之间有竖线，有的没有。

### P2-1　首页信息层级（3 个具体缺陷）

1. **列表标题跑到搜索框右侧**：`最近使用 0 个文件` 位于工具栏最右端、搜索框之后。用户的阅读顺序变成"先看到控件，后知道在看什么"。列表标题必须在控件之前（左侧）。
2. **第 5 张卡破坏模板**：前 4 张有品牌色板（蓝 W / 绿 X / 红 P / 紫 M），第 5 张"打开本地文件"只有灰色描边图标，副标题是一长串 `.docx / .xlsx / .xlsm / ...`。同尺寸同边框却不同语义，读者会以为它是"第 5 个 app"。
3. **1100px 下第 5 张撑满整行**：`flex: 1 1 calc(50% - 5px)` 在最后一行只剩一个元素时拉成通栏横幅，右侧大片空白，图文比例失衡。
4. **空状态是断头路**：只有一句提示文字，没有主 CTA。用户此刻最想做的事（新建文档）没有入口。

### P2-2　小命中区（24px 以下）

`.tab-close` 16×16、`.tree-chevron` 16×16、`.folder-add-btn` 22×22。桌面端 WCAG 2.5.8（AA）要求 24×24。标签页关闭按钮是最常被点的目标之一，16px 对触控板用户偏小。

## 3. 优化方案

### 3.0 路线：先契约、再比例尺、最后结构

顺序不能倒。色值契约不先定，后面所有 token 调整都要重算对比度；比例尺不先收敛，抽共享组件时会把 12 档圆角一起搬过去。

| 步 | 目标 | 改动面 | 风险 | 验收 |
| --- | --- | --- | --- | --- |
| 1 | 修 3 处对比度 + 统一焦点环 | `tokens.css` + 3 个 css 文件，约 20 行 | 极低（纯取值） | 对比度脚本全绿 |
| 2 | 墨色收敛 3 级 + 圆角/间距比例尺 + `light-dark()` 合并暗色 | `tokens.css` 重写（-110 行）+ 各 app 别名不动 | 中（需在浅+暗各看一遍首页与编辑器） | token 引用率 > 0；暗色层级可见 |
| 3 | 抽 ribbon 骨架 + 首页层级重排 | `packages/ui/src/ribbon.*` + `home.css`/`Home*.tsx` | 中高（触及 5 个 app） | 只迁 docs + sheets 两个最多规则的先对齐 |

### 3.1 第一步：色值契约（每个值都算过）

```css
/* tokens.css — 浅色三级墨色 + 图标色（全部满足 WCAG AA） */
:root {
  --ink-1: #242424; /* 15.52 on #fff，正文 */
  --ink-2: #55595f; /*  7.05 on #fff，次要正文（原 secondary 6.04 提深，拉开层级） */
  --ink-3: #6c7178; /*  4.59 on #f6f7f9，元信息（原 tertiary 2.85 → 达标） */
  --icon-default: #878e96; /* 3.31 / 3.09 / 3.17，非文本 ≥3:1 */
  --accent-ink: #0a63c9; /*  5.38 on #f6f7f9，accent 的"可作文本色"版本 */
}
```

要点：
- **`--accent` 保持 `#0f7fff` 不动**（3.82 作为 3:1 的图形色、焦点环是合规的），另开 `--accent-ink` 专供文字。这是 Carbon/SAP 的标准做法：图形色与文字色必须是两个 token。
- `--icon-muted: #b9bfc7` → 用 `--icon-default: #878e96`；若确有"纯装饰"用途，保留一个新名字 `--icon-decorative` 并约定**只许配 `aria-hidden`**。
- 焦点环统一到一个 token + 一条策略：

```css
:root {
  --focus-ring: 2px solid var(--accent);
  --focus-offset: 2px;
}
:where(button, a, [tabindex], input, select, textarea):focus-visible {
  outline: var(--focus-ring);
  outline-offset: var(--focus-offset);
  box-shadow: none; /* 清掉两处自造的光晕 */
}
```

然后删掉 `home.css:236`、`home.css:888` 两处 `box-shadow` 焦点，给 `tabbar.css` 的 4 个按钮补 `:focus-visible { outline: var(--focus-ring); outline-offset: -2px }`（内缩是因为它们贴着条带边缘）。

### 3.2 第二步：墨色收敛成 3 级 + 别名映射

不要逐个改 584 处 `var(--text-*)`。保留旧名字、改指向：

```css
:root {
  --ink-1: #242424;
  --ink-2: #55595f;
  --ink-3: #6c7178;

  /* 旧名保留为别名：调用点不动，语义收敛 */
  --text: var(--ink-1);
  --text-primary: var(--ink-1);
  --text-dim: var(--ink-2);
  --text-secondary: var(--ink-2);
  --text-muted: var(--ink-2);
  --text-tertiary: var(--ink-3);
}
```

暗色只覆盖 `--ink-*` 三个值（`#e4e4e4` / `#a6a6a6` / `#909090`，实测 13.11 / 6.85 / 5.22，对 `#2a2a2a` 分别为 11.29 / 5.90 / 4.50）。别名自动跟随，**暗色下层级不再塌陷**。

顺带把暗色两份副本合并。Electron 45 对应 Chromium 140+，`light-dark()`（Chrome 123+）可用：

```css
:root {
  color-scheme: light;
  --surface: light-dark(#ffffff, #1e1e1e);
  --bg-content: light-dark(#fafafa, #1a1a1a);
  --ink-1: light-dark(#242424, #e4e4e4);
  /* ... 每个 token 一行，替代两份 110 行区块 */
}
[data-theme='dark'] { color-scheme: dark; }
[data-theme='light'] { color-scheme: light; }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) { color-scheme: dark; }
}
```

这一改把 `tokens.css` 从 201 行压到约 95 行，且**根除"改浅色忘记改暗色"这一类 bug**。`color-scheme` 已经是现有的切换机制（`tokens.css:82/140`），所以不需要动主题控制器。

暗色抬升：`--surface` 从 `#1e1e1e` 提到 `#242424`（对 `#1a1a1a` 为 1.121），卡片就能靠亮度和 1px 线双重区分。

### 3.3 第二步（并行）：圆角与间距比例尺

```css
:root {
  --radius-2: 2px; /* 仅限 1px 描边的细节元素（选区、指示条） */
  --radius-4: 4px; /* 小控件：复选框、标签、菜单项 */
  --radius-6: 6px;
  --radius-8: 8px; /* 卡片、面板、输入框 */
  --radius-12: 12px; /* 容器、模态 */
  --radius-full: 999px;

  --space-1: 2px;  --space-2: 4px;  --space-3: 6px;
  --space-4: 8px;  --space-5: 12px; --space-6: 16px;
  --space-7: 24px; --space-8: 32px; --space-9: 40px;
}
```

迁移规则（机械可执行）：`1px/2px/3px → 2px`；`5px/6px/7px → 6px`；`10px → 8px`（贴边元素）或 `12px`（容器）；`16px` 保留。**先只改 token 定义与新代码**，存量在碰到的文件里顺手替换，不做全仓一次性替换——517 处一起动无法 review。

字号收敛：把 11px → 12px、13px → 14px（正文）或 12px（元信息）、17px → 16px、20px → 18px、28px → 24px。收敛后只需 6 档：12 / 14 / 16 / 18 / 24 / 28。

### 3.4 第三步：把 ribbon 骨架抽进 `@yiioffice/ui`

只抽**骨架与度量**，不抽业务：

```
packages/ui/src/ribbon.tsx        Ribbon / RibbonTabs / RibbonTab / RibbonGroup / RibbonBigButton
packages/ui/src/ribbon.css        组名 caption、组间分隔线、两行网格、图标网格
```

约束：
- `RibbonGroup` 必须有 `label`（组名），并在 CSS 里固定为 20px 高的底部通栏——**从结构上杜绝"有的组没名字"**。
- 图标尺寸收敛到 16 / 24 两档（`--ribbon-icon: 16px`、`--ribbon-icon-lg: 24px`），用 8px 基线网格对齐。
- 组内网格固定两行（24px + 20px），右上角的"单行组"用 `row-span: 2` 填满，消除 L 形空洞。
- 迁移顺序：**docs → sheets → slides → pdf → markdown**（按规则数从多到少），每迁一个跑该 app 的视觉用例。

这个改动收益最大也最贵，建议单独排期，不要和前三步混在一个 PR。

### 3.5 门禁升级：让退化无法合入

现有 `check-theme-colors.mjs` 是 diff 式的，所以 567 处存量裸色永远不会被清理，也不会变多——是"冻结"而不是"收敛"。两个务实的补充：

1. **对比度门禁**（新增 `tools/check-theme-contrast.mjs`，全量跑，不依赖 diff）：读 `tokens.css` 解析 `--ink-*` / `--surface-*` 的浅暗两套值，断言 `ink × surface` 最小比值 ≥ 4.5、`--icon-default × surface` ≥ 3.0。任何新 token 或改色立刻被拦。
2. **裸色棘轮**（扩展 1 的脚本）：把每个文件的裸色计数写进 `tools/theme-raw-colors.baseline.json`，**只允许下降**。新增一处就红，顺手清理一处就能降基线。这比"一刀切禁止"现实得多，也能让 docs 那 216 处慢慢还掉。

### 3.6 首页修复（可与前几步并行）

1. **标题前置**：把 `最近使用 N 个文件` 移回工具栏最左，`filter-pills` 与 `file-search-group` 在其右。`space-between` 改成 `flex-start` + `margin-left:auto` 给搜索组。
2. **第 5 张卡降级为"次要动作"**：不参与 5 列网格（`flex: 0 0 auto` 或放到快捷区下方单独一行），或给它一个中性色板（`--surface-subtle` 底 + `--icon-default` 图标），并在副标题里只留 `支持 docx / xlsx / pptx / pdf / md`。

## 5. 明确不建议做的事

1. **不要重画标签栏**。它的度量有 Chrome 对照，是资产不是负债。
2. **不要动文档内容色**（纸张、单元格、图表调色板）。它们与 chrome token 的隔离是刻意设计，混用会让导出结果和屏幕不一致。
3. **不要为了"设计感"加大圆角或玻璃拟态**。这是一个模仿 Office 的桌面套件，克制是它的核心气质。
4. **不要跑 `npx prettier --write`**。仓库没有 prettier 配置，默认值（双引号 + 分号 + 80 列）会毁掉现有单引号/无分号风格（项目笔记里已记录过一次 6 行改动膨胀成 199 行 diff 的事故）。
5. **不要一次性替换 517 处 `border-radius`**。按 §3.3 的"新代码遵守 + 顺手改"策略推进。
