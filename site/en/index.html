Editors

From a file to a deliverable.

Every editor opens as a tab in one workspace, hosted by a Go-side tab manager. Switching tabs only shows and hides — scroll position, cursor and undo stacks all stay exactly where you left them.

W

Docs

A Word-style ribbon (Home / Insert / Draw / Design / Layout / References / Review / View), format painter and paste special, separate East-Asian / Latin fonts, image crop, background removal and rotation, find and replace, word count, zoom and reading mode; paragraph-patch saves keep everything you did not touch byte-identical.

.docx · Tiptap 3 + docx-engine

X

Sheets

Formulas and a function library, conditional formatting, data validation, sort and filter, tables, notes and drawings, find and replace; reading and saving run through the Go-side OOXML patch gateway (excelize), so Office opens what you save as-is.

.xlsx · .xlsm · .csv · .tsv · Univer 1.3

S

Slides

Ribbon-style editing (Insert / Draw / Design / Transitions / Animations / Slide Show / Review), text, shape, picture and table editing, transitions and animation effects; EMU→px high-fidelity rendering with element-patch saves that rewrite only the nodes you changed.

.pptx · Konva 10 + pptx-engine

P

PDF

Viewing and navigation (thumbnails, page jump, zoom, fit modes); page operations: merge, split, extract pages, insert PDF, replace pages, N-up, grid cut, crop, page size, page-image export, blank pages. Annotations and content-stream editing are beyond the engine's boundary — those entry points are removed rather than left to fail on click.

.pdf · pdf.js 6 + pdfcpu

M

Markdown

WYSIWYG and source views, tables, code blocks and images; Mermaid diagrams and KaTeX math render inline, and JSON and plain text get their own editing modes.

.md · .txt · .json · Tiptap + CodeMirror 6

Export

Docs / Sheets / Slides / Markdown export to PDF; Docs also to HTML and DOCX. The --headless-export CLI converts without opening a window and --json emits one machine-readable line — all on your machine, nothing uploaded, no quotas.

pdf · html · docx · headless CLI

Your files, your call.

Opening, editing and saving all happen on your own disk. The app never uploads, syncs or backs up anything for you — where a file lives and what it is called stays your decision.

See where the network boundary is
01

Works offline

Editing, saving, searching and conversion all run locally. The only default outbound behaviour is loading remote images referenced by a document; update checks never run on their own — they start only when you trigger them in settings.

02

Saves keep formatting

Saving is an OOXML patch: only the edited nodes are rewritten, every other byte stays as it was. Styles, comments, embedded objects and macros survive, and MS Office or WPS opens the result as usual.

03

No account, no ads

No registration, no usage telemetry, no paid entry points hidden in the UI; features the engines cannot provide have their entry points removed instead of left as buttons that fail on click — the main screen is just your own file list.

Capabilities

The hard parts, handled outside the editors.

Saves that never corrupt, crashes that never lose content, search that actually hits Chinese text — the unglamorous parts are what you rely on every day.

Atomic writes

Every save goes through a temporary file plus rename, so a crash or power cut cannot leave half a file behind.

Local full-text search

A Go-side SQLite (FTS5) index over names, paths and extracted text; CJK goes through bigram + unigram streams, so two-character words match inside longer runs. fsnotify applies 400 ms-debounced incremental updates — folder changes sync live, no restart.

Multi-tab host

Tabs are managed centrally by a Go-side host; switching preserves editor state whole, tabs detach into their own windows, and closing is guarded against unsaved changes.

Headless export

--headless-export converts to PDF without a window, and --json emits one structured line for scripts and batch jobs.

Zip-bomb defence

zip-gate rejects archives whose parts inflate past what they declare before anything materialises them — one defence shared by the DOCX and PPTX engines.

Server mode & Docker

-tags server builds a pure HTTP server (no GUI, port 8080 by default) and packages it as a distroless image — one codebase, two shapes.

go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0 installs the wails3 CLI; installers and portable zips ship a SHA-256 sidecar. 
# Install frontend dependencies (one npm workspace install)
cd frontend && npm install && cd ..

# Generate bindings, start the Vite dev server (:5178), rebuild and run
wails3 dev
# Production build (build/bin/YiiOffice.exe)
task build

# NSIS installer + SHA-256 sidecar (dist/)
task package:windows

# Server-mode binary / distroless Docker image
task build:server
task build:docker
# Backend: vet and unit tests
go vet ./...
go test ./internal/...

# Frontend: typecheck, unit tests, full renderer build
npm --prefix frontend run typecheck
npm --prefix frontend test
npm --prefix frontend run build

# E2E: Playwright against the real Go backend (server build)
task e2e
CI (GitHub Actions) runs the Go, frontend and E2E stages in order on every push / PR; the UI ships in English and Chinese, with strings in @yiioffice/i18n.

FAQ

Things you might want to ask first.

Do I need an account or a network connection?
Neither. There is no account system and nothing is uploaded; editing, saving, search and conversion all happen locally. Update checks never run on their own — they start only when triggered from the settings UI, and no usage data is collected.
Can MS Office / WPS open the files after saving?
Yes. Saves are OOXML patches: only edited nodes change, the remaining bytes stay as they were, so the structures and extended properties Office relies on are preserved.
Can I annotate or edit text in a PDF?
No. The PDF engine here is pdfcpu, which manipulates page structure (merge, split, crop, page replacement and so on). Content-stream editing is beyond its capability boundary, so those entry points are hidden. Viewing, navigation and page operations all work.
Does Chinese text search work?
Yes. The index emits bigram and unigram streams for CJK, working around the fact that FTS5 unicode61 does not segment continuous Chinese text.
Can it be deployed on a server?
Yes. task build:server or task build:docker produces the HTTP shape, listening on port 8080 by default; binding to a non-loopback address prints a startup warning, so keep it behind a trusted network or a reverse proxy.
wails3 dev started, but an editor tab shows a white page?
Check that the Vite dev server (:5178) is alive — every editor tab loads from it, so a blocked port or a crashed renderer shows a blank tab. Re-running wails3 dev brings it back.

Open source — go ahead and change it.

The code, the component splits and the build scripts are all in the repository, with no hidden paid modules. Want to add an editor, reskin the palette, or make one format's read/write even more faithful? Just start hacking.
